# 📘 Обзор практических работ 19–23

Ниже представлен краткий обзор выполненных практических занятий по дисциплине **«Фронтенд и бэкенд разработка»**. Каждая работа сопровождается ссылкой на соответствующий код в репозитории.

## 🗃️ Практическое занятие №19: Работа с реляционными СУБД на примере PostgreSQL

**Цель:** Научиться подключать реляционную базу данных к Node.js-приложению, выполнять CRUD-операции и использовать ORM Sequelize.

**Выполнено:**
- Установка PostgreSQL (локально или через ElephantSQL).
- Создание базы данных и таблицы `users` с полями: `id`, `first_name`, `last_name`, `age`, `created_at`, `updated_at`.
- Реализовано API с эндпоинтами:
  - `POST /api/users` – создание пользователя
  - `GET /api/users` – получение списка всех пользователей
  - `GET /api/users/:id` – получение одного пользователя
  - `PATCH /api/users/:id` – обновление данных
  - `DELETE /api/users/:id` – удаление пользователя
- Использована ORM `Sequelize` для взаимодействия с PostgreSQL.
- Добавлена валидация полей и обработка ошибок.

**Стек:** Node.js, Express, PostgreSQL, Sequelize.

## 🗃️ Практическое занятие №20: Работа с NoSQL СУБД на примере MongoDB

**Цель:** Освоить подключение и работу с документоориентированной базой данных MongoDB через ODM Mongoose.

**Выполнено:**
- Установка MongoDB (локально) и настройка аутентификации.
- Определена схема пользователя (`User`) с полями: `first_name`, `last_name`, `age`, `created_at`, `updated_at`.
- Реализован аналогичный набор CRUD-маршрутов:
  - создание, чтение всех, чтение одного, обновление, удаление пользователя.
- Использованы методы Mongoose: `create`, `find`, `findById`, `findByIdAndUpdate`, `findByIdAndDelete`.
- Добавлены индексы для оптимизации поиска.

**Стек:** Node.js, Express, MongoDB, Mongoose.

## ⚡ Практическое занятие №21: Кэширование с использованием Redis

**Цель:** Добавить кэширование часто запрашиваемых данных (список пользователей, товаров) с помощью Redis; реализовать инвалидацию кэша при изменении данных.

**Выполнено:**
- Подключен Redis (локально через Docker или напрямую).
- Созданы middleware `cacheMiddleware` и функция `saveToCache` для чтения/записи в Redis.
- Защищённые маршруты `GET /api/users`, `GET /api/users/:id`, `GET /api/products`, `GET /api/products/:id` обёрнуты в кэширование.
- Установлены TTL:
  - для пользователей – 60 секунд,
  - для товаров – 600 секунд.
- Реализована инвалидация кэша:
  - при обновлении или блокировке пользователя – удаляются ключи `users:all` и `users:id`,
  - при создании, обновлении или удалении товара – удаляются ключи `products:all` и `products:id`.
- Ответы от сервера помечены полем `source: "server"` (из базы) или `source: "cache"` (из Redis).

**Стек:** Node.js, Express, Redis, JWT, RBAC.

## ⚖️ Практическое занятие №22: Балансировка нагрузки в веб-приложениях

**Цель:** Настроить балансировку HTTP-трафика между несколькими backend-серверами с помощью Nginx и HAProxy.

**Выполнено:**
- Созданы три экземпляра Node.js-приложения, запущенных на портах 3001, 3002, 3003.
- Написан конфигурационный файл `nginx.conf` с upstream-группой:
  - два основных сервера (3001, 3002) с параметрами `max_fails=2 fail_timeout=30s`,
  - один резервный сервер (3003) с директивой `backup`.
- Настроен Nginx для прослушивания порта 80 и проксирования запросов к upstream-группе.
- Проверена работа алгоритма **Round Robin** – запросы поочерёдно идут на 3001 и 3002.
- Протестирована отказоустойчивость:
  - при остановке одного из основных серверов трафик автоматически переключается на оставшийся рабочий;
  - при остановке обоих – на резервный.
- В качестве альтернативы настроен HAProxy на порту 8081 с аналогичной конфигурацией (алгоритм roundrobin, проверка здоровья через `/health`).

**Стек:** Node.js, Express, Nginx, HAProxy, командная строка (curl).

## 🐳 Практическое занятие №23: Контейнеризация приложений с Docker

**Цель:** Упаковать приложение с балансировкой нагрузки в контейнеры с помощью Docker Compose, развернуть всё в среде WSL.

**Выполнено:**
- Установлен WSL2 и Docker внутри Ubuntu (WSL).
- Написан `Dockerfile` для backend-сервиса (Node.js + Express).
- Создан файл `docker-compose.yml`, описывающий четыре сервиса:
  - три бэкенда (`backend1`, `backend2`, `backend3`) с переменной окружения `SERVER_ID`,
  - один контейнер Nginx, использующий официальный образ `nginx:alpine`.
- Конфигурация Nginx проброшена через volume (`./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro`).
- Все сервисы объединены в общую сеть (`app-network`), что позволяет Nginx обращаться к бэкендам по их именам (`backend1`, `backend2`, `backend3`).
- Запуск всего стека: `docker compose up --build`.
- Проверена балансировка (чередование `backend-1` и `backend-2`) и отказоустойчивость (остановка контейнера `docker compose stop backend1`).

**Стек:** Docker, Docker Compose, Node.js, Express, Nginx, WSL.
